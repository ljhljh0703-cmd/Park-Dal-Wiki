# 문서가 쌓이면 생기는 문제, 그리고 규칙 3개

## 문제 정의

노트가 늘면 **내용이 부족해서가 아니라 어느 게 진짜인지 몰라서** 못 씁니다. 네 가지 형태로 나타납니다.

1. **레거시** — 옛날 문서가 지워지지 않은 채 남아 있다. 읽는 사람도 AI도 그게 현행인 줄 안다.
2. **중복** — 같은 내용이 두 곳에 있다. 한쪽만 고치면 둘이 갈린다. 갈린 걸 나중에 발견한다.
3. **버전** — `rev1`, `rev2`, `최종`, `최종_진짜최종`. 파일 이름으로는 최신을 알 수 없다.
4. **덮어쓰기 사고** — 문서를 통째로 다시 쓰다가 안에 있던 절을 소리 없이 날린다.

> 이건 가정이 아닙니다. 이 저장소를 만드는 하루 동안 네 가지가 전부 실제로 일어났습니다 —
> 같은 파일이 두 경로에 있어 한쪽만 고쳐질 뻔했고(중복), 관찰 기록이 rev1·rev2·rev3로 늘었고(버전),
> AI가 규약 문서를 다시 쓰다가 「역할 정의」 절을 통째로 날렸습니다(덮어쓰기 사고).

## 규칙 3개 — 이것만 지키면 됩니다

### 1. 지우지 않는다. 표시하고 옮긴다.
문서를 버릴 때 삭제하지 않습니다. 맨 위에 한 줄을 적고 `_archive/` 로 옮깁니다.

```
> ⛔ 폐기 2026-08-29 — 대신 [[새 문서 이름]] 를 보세요.
```

지운 문서는 왜 지웠는지도 같이 사라집니다. 남겨 두면 나중에 "이거 왜 안 쓰기로 했더라"에 답할 수 있습니다.

### 2. 같은 내용이 두 곳에 있으면, 한 곳이 정본이다.
사본 맨 위에 반드시 이 한 줄을 답니다.

```
> ⛔ 사본입니다 (2026-08-29 기준). 정본 = `wiki/실제경로.md` — 고칠 때는 정본만 고치고 다시 복사하세요.
```

이 줄이 없는 사본은 **반드시 갈립니다.** 시간 문제입니다.

### 3. 새 버전은 새 파일이 아니라 같은 파일이다.
`rev2.md` 를 만들지 않습니다. 원래 파일을 고치고, 맨 위 `updated` 날짜를 바꿉니다.
이전 판이 정말 필요하면 그때만 `_archive/이름-2026-08-29.md` 로 한 부 떠 둡니다.

## 문서 맨 위에 붙이는 세 줄

```
---
status: active        # active(현행) | superseded(대체됨) | archived(보관)
updated: 2026-08-29
supersedes:           # 이 문서가 대체한 옛 문서가 있으면 그 이름
---
```

더 늘리지 마세요. 세 줄이면 "이게 현행인가"에 답할 수 있고, 그게 전부입니다.
